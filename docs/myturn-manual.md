
# 마이턴옥션 매뉴얼 만들기 (주제 → 운영 배포까지)

사용자가 주제만 말하면 아래 순서로 운영 사이트 등록까지 진행한다. 사용자가 확인하는 자리는 '원고' 한 번이고, 그 뒤는 배포·등록까지 이어서 하고 결과 화면을 보여 준다. 답은 한국어로 짧게.

기준 견본
- 1호 「매각불허가 신청」 web/manual/unpermit.html, 2호 「명도 · 인도명령」 web/manual/evict.html
- 운영 주소 https://terryauction-6b374.web.app/web/manual/<슬러그>.html
- 등록 위치 https://terryauction-6b374.web.app/web/#/store › 관리(운영) 탭
- 저장소: Mac ~/gitsource/terry_auction (배포는 여기서만. Windows 사본은 쓰지 않는다)

## 1. 조사 (사실만, 요점 위주)
- 앱 매뉴얼 탭이 남아 있으면 뼈대로만 참조하고(출처로 적지 않음), 내용은 반드시 외부 전문 자료로 조사한다.
- 법령 원문: 국가법령정보센터 / korea.legal 조문 페이지에서 조·항·호 확인.
- 판례: 대법원 결정·판결 4~8건(선고일·사건번호·결론). 날짜와 사건번호는 판례 페이지에서 한 번 더 확인.
- 실무: 기한·비용·서류·제출처. 확인 안 되는 수치는 지어내지 말고 '경매계/집행관사무소 확인'. 기사 수치는 출처·날짜와 함께 '예시'로.

## 2. 원고 먼저 (필수, 사용자 확인 1회)
- 목차 + 장별 상세 원고를 .md 로 보여 주고 확인받는다. 표준 목차(주제에 맞게 넣고 뺀다):
  00 요약(5칸) / 01 개념(비유 1개) / 02 일정(타임라인+구간표) / 03 요건·유형표 / 04 판례 카드 / 05 누가 / 06 절차 / 07 서식 예시(+빈칸 양식 복사) / 08 결과별 대응(흐름도+표) / 09 체크리스트(글자형) / 10 FAQ / 11 출처
- 문장은 짧게, 요점과 팩트만. 조문 (제123조②), 판례 '대법원 2010. 2. 16. 2009마2252'.
- 같은 원고에 카드 문구(제목·한줄설명·내용)와 표지 글자(6장 형식)도 적는다.

## 3. 웹 매뉴얼 페이지
- 1·2호 파일을 바탕으로 내용만 바꾼다: 마이턴옥션 토큰(남색 #213366 · 주황 #f4700a · 블루그레이 바탕), 남색 머리띠(로고 + '콘텐츠 · 매뉴얼' + '← 콘텐츠로 돌아가기'), 장 줄 + 왼쪽 목차, 밤 화면. 경로 '콘텐츠 › 매뉴얼 › <주제> · 기준일'.
- 그림은 SVG·HTML(타임라인, 흐름도, 서식 예시). 외부 이미지 쓰지 않음.
- 체크리스트는 글자형만(ul/li 빈 네모). 체크박스·localStorage 등 브라우저 저장·서버 저장 없음. 빈칸 양식 복사 단추는 둠.
- ?embed=1 이면 html.embed — 남색 머리띠·바닥글 숨기고 장 줄 top 0.
- 네 글자 UI 문구는 붙여 쓴다(예: 명도절차). 완성 문서(doctype·lang=ko·charset·viewport, title·style 은 head 안).
- 페이지 끝에 기준일과 '일반 정보이며 법률 자문이 아님' 한 줄.

## 4. 검증
- 조문·기간·금액을 출처와 다시 대조.
- 1440·400 폭과 ?embed=1 에서 가로 넘침·스크립트 오류 없음, 체크리스트에 입력칸·저장 코드 없음.

## 5. 운영 배포
- 사이트에는 매뉴얼 기반이 이미 들어 있다: predeploy 가 web/manual/*.html 을 dist/web/manual 로 복사, 콘텐츠 화면의 보기 팝업·HTML 표지·공유 아이콘·무료보기/유료보기. 새 매뉴얼은 파일 하나 추가 + 배포.
- **Mac 에서 직접 실행 중일 때(VS Code Claude Code 등, 터미널 사용 가능)**: 저장소에서 `npm run build && npx --yes firebase-tools deploy --only hosting` 을 직접 실행한다(firebase 단독 명령은 없음). 실행 전 `git status` 로 앱 쪽(web/manual 밖)에 커밋 안 된 변경이 있으면 멈추고 사용자에게 묻는다.
- **원격(클라우드 세션, Mac 에 연결)일 때**: 자동 배포 에이전트(launchd `com.myturn.manual-deploy`, scripts/manual-deploy.sh)를 쓴다.
  1. 매뉴얼 파일을 쓴 뒤 저장소 `.manual-deploy/request` 에 새 값(예: `evict 2026-11-09T11:40+09:00`)을 쓴다(device_commit_files, /mnt/user-data/outputs 의 stagedPath).
  2. Mac 이 빌드·배포하고 `.manual-deploy/log.txt` 에 request · start · commit · manuals · exit · end 를 남긴다(보통 1~3분).
  3. log.txt 를 읽어 request 값이 같고 `exit: 0` 인지 확인.
  - `blocked:` = 앱 쪽에 커밋 안 된 변경이 있어 멈춤. 목록을 보여 주고 묻는다(임의로 커밋·되돌리지 않음).
  - log 가 안 바뀌면 Mac 이 잠들었거나 에이전트 미설치. 설치는 한 번만: `bash ~/gitsource/terry_auction/scripts/setup-auto-deploy.sh`.
  - .vscode 폴더는 원격 파일 도구로 쓸 수 없다.
  - device_commit_files 는 같은 stagedPath 를 다시 쓰면 예전 내용이 들어갈 수 있다 → 매번 새 폴더(/mnt/user-data/outputs/u<시각>/)에 만들어 보내고, 크기·내용을 다시 확인한다.
- 운영 주소를 열어 페이지 제목이 매뉴얼 제목인지 확인한다(아니면 사이트 기본 화면으로 떨어진 것 = 미배포). 열리기 전에는 등록하지 않는다.

## 6. 콘텐츠 › 관리에 등록 (브라우저)
1. 콘텐츠 › 관리 탭: [data-act="store-tab"][data-v="manage"]
2. 종류 '매뉴얼', 가격 '무료', 꼬리표 '실전'(입문 주제면 '기초')
3. 제목은 '<주제> 매뉴얼' — **[실전] 같은 꼬리표를 제목에 넣지 않는다**(카드가 자동으로 붙임). 한줄설명 · 내용(1,000자 이하)
4. 표지 그림은 넣지 않는다. 내용 맨 끝에 아래 블록을 붙이면 HTML 표지가 그려지고 자세히보기에서는 감춰진다:
```
[표지]
번호: 03            (기존 매뉴얼 수 + 1)
머리글: 실전 경매 매뉴얼 · <단계>
제목: <첫줄> / <둘째줄>
부제: <한 줄>
일정: 이름(작은글) > 이름(작은글) > …   (3~4개)
강조: 1-2 <구간 설명>
칩: 가 · 나 · 다
근거: <법조문>
기준: YYYY.MM 기준
[/표지]
```
5. 링크 칸에 운영 주소. 상태 '공개' → '올리기'. 고칠 때는 '고치기' → '고친내용저장'. 사용자가 직접 고친 칸은 덮어쓰지 않는다.
- 입력은 값 설정 후 input 이벤트를 보내면 반영된다. 올리면 폼이 비워진다 — 목록에서 제목으로 확인.

## 7. 영상 대본 (매뉴얼마다 필수)
- 매뉴얼을 만들 때마다 유튜브용 대본을 함께 쓴다: **쇼츠 약 55초(세로)** + **롱폼 약 3분(가로)**.
- 형식: 쇼츠는 시간 · 화면 · 대사 · 자막 표, 롱폼은 장별 대사·자막. 매뉴얼과 같은 사실·수치만 쓰고, 마지막에 '마이턴옥션 › 콘텐츠 › 매뉴얼' 안내.
- 참고 영상이 있으면 순서·표현을 그대로 따르지 않고 매뉴얼 구성대로 다시 짠다.
- 저장: 저장소 docs/scripts/<슬러그>.md, 사용자에게 파일로 전달.

## 8. 마무리
- 콘텐츠 › 매뉴얼 탭 카드, 자세히보기, 무료보기 팝업을 스크린샷으로 보여 준다(제목 줄 정렬, 단추 문구, 팝업 안 매뉴얼 표시 확인).
- 출처 목록을 붙인다.

## 하지 않을 것
- 앱 화면 파일(src/pages)은 사용자가 명시하기 전까지 건드리지 않는다.
- 최신 저장소(Mac)가 아닌 곳에서는 배포하지 않는다.
- 표지를 그림 파일로 넣지 않는다. 체크리스트에 체크·저장 기능을 넣지 않는다.
- 법률 자문처럼 단정하지 않는다.
- 사용자에게 스킬 카드 저장·연결·설치 같은 조작을 부탁하지 않는다. 규칙은 이 문서에 직접 반영한다.
- 참고 영상의 순서·구성을 그대로 따르지 않는다(카테고리로 묶고 순서를 재구성). 참고 영상·채널(유튜브 등)은 출처·참고에 적지 않는다.
- 출처·참고에 마이턴옥션 앱 매뉴얼 탭(#/manual/...) 링크나 '마이턴옥션 매뉴얼'을 넣지 않는다(종전 탭은 삭제 예정이고 저작자가 마이턴). 다른 매뉴얼은 '콘텐츠 › 매뉴얼의 ○○ 매뉴얼' 글자로만 가리킨다.
